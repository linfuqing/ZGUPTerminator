**Cursor 规则**：`.cursor/rules/bot-relay.mdc`（Relay 目录）、`.cursor/rules/bot-recording.mdc`（Recording 目录）、`.cursor/rules/unity-project.mdc`（Burst/热路径规范）。

**热路径原则（摘要）**：帧性能 > 内存/并发安全 > 停服 Dispose；禁止为 Editor 退出警告牺牲 Job。详见 [架构约束 §5.2](./联机机器人-架构约束.md#52-热路径优先级性能--安全--dispose)。

**PlayMode 交付门禁（摘要）**：改 Relay / 模拟真人操作 → EditMode `Regression` → EditMode `category=PlayMode` 单会话门禁全绿（内部覆盖 6 个行为点，含 farm-wide 匹配独占与 Bot-vs-Bot 回退）→ 再人工 Play。详见 [架构约束 §6.1](./联机机器人-架构约束.md#61-playmode-验收模拟真人操作交付门禁)。

**包修改（一句话）**：原则上不改 ZGUP 包；若完整评估后改包收益最大，由**负责人**自行改包（如 `AddDriver`）；工程侧只提方案，Server 撮合逻辑不为 Bot 特化。

**反射**：Editor/Legacy 录制路径已改用 ZG 包公开 API（`GetPendingSendSlotCount` / `TryReadPendingSend` / `TryEnqueueSyntheticData`）；Relay 热路径无反射。

## 当前架构（一句话）

**Bot 与 ReplyServer 同进程共部署**（`Assets/Scenes/Server.unity` + `BotCoDeployBootstrap`）：单 Bot Listen Driver + `BotRelayManager` 虚拟端口；Connect / link 与 Server→Bot 下行处理 UTP，Connect 后业务 app 经 Server inject API；Farm 内 `minBots`～`maxBots` 个 agent，**不是**多个 Headless 进程连 Server。
