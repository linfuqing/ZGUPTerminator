# 联机机器人 — 发布与测试分离

> **目的**：明确「共部署交付代码」与「Editor 自验证」的边界，避免为跑通 PlayMode 在发布热路径上掺入测试妥协。  
> **权威层级**：发布行为以 [联机机器人-架构约束.md](./联机机器人-架构约束.md)（M1–M7）为准；测试以本文 + [架构约束 §6.1](./联机机器人-架构约束.md#61-playmode-验收模拟真人操作交付门禁) 为准。

---

## 1. 两个目标（不可混写）

| 维度 | **发布目标**（Release） | **测试目标**（Editor / PlayMode） |
|------|-------------------------|-----------------------------------|
| **部署形态** | `Server.unity` 与 Bot Farm **同进程共部署** | 加载 `Server.unity` + `World.Update`，模拟真人操作 |
| **热路径** | 单 Bot Listen Driver + `BotRelayFarmNative`；Connect/link 用 `EnqueueToListen`，业务用 `BotRelayInjectQueue`，下行用 `TryDequeueToBot` | 与发布相同 Server/Bot 热路径；**额外**可模拟第二个「真人 host」 |
| **Bot 连接** | Init 采 Connect/hello/link UTP 模板；Connect 后业务经 Server inject API；**无** `ClientData` | Bot 仍走 Farm 注入；host 可用 Editor 专用手段 |
| **状态写入** | Bot **不写** `ReplyMessageShared`（M6） | Host 模拟可写 `ReplyMessageShared`（仅测试） |
| **约束文档** | [架构约束](./联机机器人-架构约束.md) 全文 | 不受 M6「禁止写 SharedStatic」约束于 **host 模拟**；仍须 PopEvents 无越界 |
| **程序集** | `Terminator.MultiplayerBot` | `Terminator.MultiplayerBot.Tests`（`includePlatforms: Editor`，TestAssemblies） |
| **允许妥协** | **仅诊断 LOG**（`[BotRelay]`、`diag*`） | HostTestClient、抓包 fixture 等 |

**一句话**：发布代码只服务「Server 里跑 N 个 Bot」；测试代码只服务「Editor 里证明这条链路与 Manual Play 一致」，且**不得**把测试专用双轨写进 WireCatalog / Farm 热路径。

## 2. 程序集划分

```
Terminator.MultiplayerBot/
├── Terminator.MultiplayerBot.asmdef              ← 发布（全平台）
├── Terminator.MultiplayerBotAssemblyInfo.cs      ← InternalsVisibleTo("Terminator.MultiplayerBot.Editor")
├── Relay/                             ← 热路径、WireCatalog、Farm
├── Bot/                               ← 共部署 Farm 的状态模型（BotState / Session / AgentState）
└── Recording/                         ← 生产读取/序列化公共类型

Terminator.MultiplayerBot.Recording/            ← Editor PlayMode 录制/Replay
Terminator.MultiplayerBot.Editor/               ← 共部署场景工具（非测试程序集）
Terminator.MultiplayerBot.Recording.Editor/     ← 录制窗口、审计工具（非测试程序集）
Terminator.MultiplayerBot.Tests/                ← Relay 测试、PlayMode 门禁
Terminator.MultiplayerBot.Recording.Tests/      ← 录制测试
```

| 程序集 | 打进包体 | 引用关系 |
|--------|----------|----------|
| `Terminator.MultiplayerBot` | 是（含微信/Android/Server） | 不引用 Editor 程序集 |
| `Terminator.MultiplayerBot.Recording` | 否（`UNITY_EDITOR`） | 引用 `Terminator.MultiplayerBot` |
| `Terminator.MultiplayerBot.Editor` | 否 | 引用 `Terminator.MultiplayerBot`；不引用 Test Framework |
| `Terminator.MultiplayerBot.Recording.Editor` | 否 | 引用运行时与录制程序集；不引用 Test Framework |
| `Terminator.MultiplayerBot.Tests` | 否 | 引用 `Terminator.MultiplayerBot` + Test Framework |
| `Terminator.MultiplayerBot.Recording.Tests` | 否 | 引用运行时、录制 Editor + Test Framework |

**规则**：新增 PlayMode / Regression / Host 模拟 → **只放 `Editor/`**；若需访问 `internal` Relay API，用 `InternalsVisibleTo`，**不要**把 `#if UNITY_EDITOR` 测试块长期留在 `Relay/`。

## 3. 发布路径（必须保持）

与 [架构约束 §1–§3](./联机机器人-架构约束.md) 一致，摘要：

1. **单 Listen Driver**（M1）— 仅 `NetworkRelayServerSystem` 驱动 `ScheduleUpdate`。
2. **Bot → Server** — 仅 Connect/link 经 `BotRelayManager.EnqueueToListen(virtualPort, utpWire)`；Connect 后业务经 `BotRelayInjectQueue` → `NetworkRelayServerInjectSingleton` → Handler（M2/M4）。
3. **Server → Bot** — `RouteSend` → `TryDequeueToBot` → Inbox（M2）。
4. **WireCatalog** — Init 一次性采 **Bot** Connect / hello / link ACK；下行结构化解包。历史业务 outbound 模板不是投递保证（M4/M5）。
5. **Agent 状态** — `BotRelayFarmNative` / `BotSessionState`；**禁止** Bot 写 `ReplyMessageShared`（M6）。
6. **匹配** — `BotMatchGuard` 禁止 Bot↔Bot（M7）。

## 4. 测试路径（Editor only）

### 4.1 验收门禁

见 [架构约束 §6.1](./联机机器人-架构约束.md#61-playmode-验收模拟真人操作交付门禁)：

1. EditMode `Regression` 全绿  
2. `category=PlayMode` 单会话门禁全绿（内部覆盖 6 个行为点，含 farm-wide 匹配独占与 Bot-vs-Bot 回退）
3. 再人工 `Server.unity` Play 复核  

MCP：`mode=EditMode` + `category=PlayMode`（**勿**用 `mode=PlayMode`）。

### 4.2 Bot 侧（与发布一致）

PlayMode 中 Bot 仍走：

```
已捕获的 Server→Bot invite → DrainInbound → PendingInvite → Agent 写 inject queue
→ Server Handler → RouteSend → bot vport
```

禁止：PlayMode 专用捷径直接改 Farm 状态冒充 Join 成功，或把业务 app 伪装成 UTP wire；EndToEnd 必须经 inject queue、Server Handler 与显式的 Server ack / Inbox 路径验证。

### 4.3 Host 侧（测试专用，非发布）

**Manual Play 真人 host**：真实 `NetworkClient` + `ClientData` + `ReplyMessageSystem`。

**当前 PlayMode**：`BotRelayHostTestClient` — 真实 `ClientData` + `NetworkClientDriver` 连 ReplyServer（`replyServerPort`，默认 1386），经 `ReplyMessageSystem` 更新 `ReplyMessageShared`（与 Manual Play 一致）。

**已移除（过渡方案）**：`BotRelayHostSimClient` / `BotRelayHostTestWires` — 第二 virtualPort + `EnqueueToListen` 注入。

Inbound 合成注入参考（录制/Replay，非 host 建队）：

- `Recording/PlayMode/NetworkClientReplayInjector.cs`
- `Relay/BotRelayInjectOps.cs`（生产业务注入）
- `Recording/PlayMode/LevelRecordingHarnessWireSystem.cs`

测试允许为 host 使用 `ClientData` 单连接；**不**表示发布 Bot 可走 `ClientData` 热路径。

### 4.4 Editor 专用资产

| 类型 | 位置 | 说明 |
|------|------|------|
| 抓包前缀 | `BotRelayWireTestFixtures.CapturedInviteWirePrefix` | Server→Bot 下行 framing 回归；不作为 Bot→Server 业务成功判定 |
| 真人 userId | `BotRelayWireTestFixtures.RealPlayerUserId` | Host 捕获 header |
| Host 状态机 | `BotRelayHostTestClient` | 真实 ClientData；`BotRelayHostMessageParser` 仅 EditMode 单元测试 |

### 4.5 录像素材门禁

发布回放端只负责忠实消费录像时间轴：每个 Server Tick 注入当时已经到期的全部 gameplay 帧，同一时间戳批次不得被固定条数限流拆开。异常素材统一通过 Editor 菜单 `Tools/MultiplayerBot/Recording Batch Audit` 检测；`CollapsedMoveTimestamps`、超出 relay packet 容量、缺失 PlayerProperty 等 Error 必须先处理或重录，不能依靠运行时慢放、丢帧或限流掩盖。
